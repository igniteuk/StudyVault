# Deployment and Google Drive

## Cloudflare Pages

1. Push the repository to GitHub with `main` as its production branch. Use a standard GitHub-hosted runner. Public repositories can use standard runners for free. For a private repository, keep runs and artifact storage within the account’s included allowance and set a spending limit. The workflow runs on changes, uses a single runner per run and keeps report artifacts for 14 days. [GitHub Actions billing](https://docs.github.com/en/billing/concepts/product-billing/github-actions)
2. In Cloudflare, open **Workers & Pages → Create → Pages → Connect to Git**, grant the integration access to this repository, and select `main`. Use no framework preset and set the output directory to `dist`. If the dashboard requires **Save and Deploy** to finish creating the project, temporarily set the build command to `exit 1` so that first ungated attempt fails.
3. In the project’s build settings, disable **automatic production branch deployments** and set the **preview branch** control to **None**. After both native triggers are disabled, set the Pages build command to `npm run build`, keep `dist` as the output, and use Node 24 for Pages builds. The workflow publishes that same build output through Wrangler. [Pages Git integration and branch controls](https://developers.cloudflare.com/pages/configuration/git-integration/)
4. Set the repository Actions variable `CLOUDFLARE_PAGES_PROJECT` to the Pages project name. In **Settings → Environments**, create `production` and `preview`. Restrict their deployment branches to `main` and `preview`, respectively. Add `CLOUDFLARE_ACCOUNT_ID` and `CLOUDFLARE_API_TOKEN` as **environment secrets** in each environment. Use a token scoped to **Account → Cloudflare Pages → Edit** for this account. Protect both branches, require the **quality** status check, and review changes to the workflow and release evidence before merging. GitHub Free supports these controls for public repositories. For a private repository without protected environments, keep automated publishing disabled until the controls are available. [GitHub deployment environments](https://docs.github.com/en/actions/how-tos/deploy/configure-and-manage-deployments/manage-environments)
5. Push to `preview` for a gated preview at `https://preview.<project>.pages.dev`. A push to `main` publishes to `https://<project>.pages.dev` when the full release gate passes. Pull requests run checks and generate reports. They have no publish step. When the Pages project variable is unset, the workflow runs checks and writes reports without publishing.

Pages serves the free `pages.dev` URLs over HTTPS. The build uses Pages’ default SPA fallback by omitting a root `404.html`. `public/_headers` sets the app security headers and enables revalidation. The service worker precaches a versioned shell, serves known routes offline, and removes older StudyVault caches after activation. Installed apps use the same browser storage origin as their corresponding site. [Pages routing and caching](https://developers.cloudflare.com/pages/configuration/serving-pages/)

## Configure optional Google Drive

1. In Google Cloud Console, create a project and enable **Google Drive API**. Use a separate project for development/preview and production. Configure Google Auth Platform **Branding**, **Audience**, and **Data Access**. For external testing, add the Google accounts that will verify sync as test users. Request the `https://www.googleapis.com/auth/drive.appdata` scope.
2. Create an OAuth client of type **Web application**. Add authorised JavaScript origins matching the exact URLs you use, with scheme and port and without paths. Examples are `http://localhost:5173` for Vite, `http://localhost:4173` or the exact loopback origin you use for local production tests, `https://preview.<project>.pages.dev` for preview, and `https://<project>.pages.dev` for production. Add a stable preview alias instead of relying on an automatically generated deployment hostname. For local testing, open the app using the registered origin and use Vite/Wrangler with the matching host and port. The GIS token flow uses JavaScript origins and a browser popup. [Google Identity Services token model](https://developers.google.com/identity/oauth2/web/guides/use-token-model)
3. Put the public client ID in `.env.local` as `VITE_GOOGLE_CLIENT_ID` for local builds. Set `VITE_GOOGLE_CLIENT_ID_PREVIEW` and `VITE_GOOGLE_CLIENT_ID_PRODUCTION` as GitHub repository variables for the matching branches. Vite exposes only the allowlisted OAuth client ID to the application. Keep client secrets, service account keys and Cloudflare credentials out of Vite variables and frontend files.
4. For public OAuth, configure the published app home and privacy URLs and satisfy Google’s branding, ownership and verification requirements. The app includes `/privacy/`. If your app needs a domain you can verify and your Pages hostname does not satisfy that requirement, keep public OAuth disabled until you have an eligible origin. A free local-first release on `pages.dev` works with both GitHub OAuth variables blank. [Google OAuth production readiness](https://developers.google.com/identity/protocols/oauth2/production-readiness/policy-compliance)

### Connection and sync behaviour

Settings loads Google Identity Services when you choose **Set up Google Drive**. **Connect Google Drive** opens the account picker. **Sync now** merges the selected account’s private app-data snapshots with this browser’s vault and uploads this browser’s latest snapshot. On a second device, use the same app configuration and account, then choose **Sync now**. Make another sync pass on the first device to pick up changes made on the second.

The app uses one snapshot per browser storage profile. For competing changes to the same item, the latest timestamp wins, with deterministic tie resolution. Keep device clocks accurate. A newer deletion hides the item across devices. Sync is manual, skips identical uploads and backs off on quota responses and transient failures. It is bounded to 5 MiB per snapshot and 24 browser profiles per account and app. A connection error leaves local revision available. [Drive application data folder](https://developers.google.com/workspace/drive/api/guides/appdata) · [Drive quota and retries](https://developers.google.com/workspace/drive/api/guides/limits)

Keep optional sync within Google's published no-cost usage thresholds. Leave the OAuth client ID blank if you want a release with no Google Cloud project or API usage. [Google Drive API pricing](https://developers.google.com/workspace/drive/api/guides/limits#pricing)

**Disconnect** or leaving Settings clears the in-memory session. If a token expires, reconnect in Settings to obtain a fresh one. To revoke access to the account, remove StudyVault from Google Account connections. Unconfigured builds show Drive as unavailable and can use local backup export and import.
